## 3.6a: the data

- `plugin/team/team.mjs`: version 2's strict schema takes `preset` and `on` in place of `kind`, and `generator`; it checks
  5 per guild and no `edits-and-checks` in the Design guild. `upgrade()` turns a version 1 team into version 2 (E8), and
  `readTeam()` reads either, so the guard and the hall see version 2 only. `toolsOf()` reads the preset. The upgrade
  changes no tool any specialist has: a test runs it over the defaults and over a team with every v3.4 shape.
- `defaults.json`: version 2, the 8 specialists with their presets, unchanged in what they do.
- The guard: an Agent call for a specialist that is off is denied, with its own reason (E10). Edits by a specialist go
  to its own permission prompt when its preset edits, as for `kind: edits` today.

## 3.6b: the API

- `POST /api/team` takes four more changes in `src/team/schema.ts`, mirrored in `team.mjs` (`team-page.test.ts` keeps
  them in step): `add-specialist` (name, guild, role, preset, skills: `team.mjs` makes the id), `change-specialist` (id,
  role, preset, skills), `delete-specialist` (id), `switch` (id, on). Deleting one takes it out of every row; a
  specialist running at that moment finishes, and the next start is denied. Each with planted-bug tests.
- `team-log.mjs` and the pane: "Specialist added: <name> (<guild>)", "Specialist changed: …", "Specialist deleted: …",
  "<name> switched on/off", names that pass the name rule only.

## 3.6c: the page

- Built from the approved mockup only. Tabs as a `tablist` (arrow keys), list rows and chips as real buttons, the skill
  list behind "+ Add skill" closes on Escape, focus kept on what you acted on, every save said in the status line
  (`role="status"`). Everything shown is React text, never HTML.
- Specialist details: name, "<Guild> guild · started by the <lead>", the switch, the role, "What it may do" (the preset's
  badge and sentence), Skills "n of 5" as chips (the name opens the skill, × takes it off with Undo), "+ Add skill" (the
  remaining skills with what each is for), Model "Sonnet, like every specialist", Started by, Its id. Change, Delete.
  Delete asks first: the lead can't start it any more, its skills stay, and switching it off is the gentler way.
- The specialist form, in the details pane: Name (Add only, with the id it will get), Guild (4 cards, locked in Change),
  "What it does, in one line", What it may do (3 cards), Skills (checkbox cards, 5 at most), Model shown.
- Skills: the list says "Used by N" or "Unused"; details show what it's for, who uses it (buttons that open each one), the
  whole text with line numbers and `checkText()`'s link and command-like flags, Change, Delete (the question names who
  loses it). The skill form: name, what it's for, the text, and a live preview with its flags beside the text; a new
  skill's id comes from its name. Refusals as in v3.4c.
- Checked in Edge (Playwright, a fresh temporary profile, a real hall on a free port): every change through the keyboard
  alone, and the tab order. Narrator and how it looks are Dima's checklist.

## 3.6d: refreshing

- `plugin/hooks/team-check.mjs`: exit 0 when the team's `generator` is this plugin's (or newer), 6 when it is older or
  the team is version 1, 4 when there is no team or it is broken; prints nothing. The pane runs it at session start and
  shows "Your team's specialist files are from an older plugin. Type /world-of-agents:setup-team-write to refresh them."
- `setup-team-write` on an existing team: rewrites the generated files and `generator` only, after checking the team as
  `readTeam()` does; it never changes `team.json`'s specialists, skills or texts. A test plants every field and compares
  before and after. A team from a newer plugin is left alone.

## Security notes

- Unchanged from v3.4c: every write goes through `POST /api/team` with the cookie, the exact Origin, the schema and the
  64 KiB cap, then `team.mjs` checks the result again and writes only in the team folder. Only Dima changes the team; the
  guard and the template keep agents out of the team folder.
- A specialist's role is the only text of Dima's in its prompt, and it is a name-rule line (no colon, no line break, no
  `#`), at most 200 characters. What limits a specialist is its tools (from the preset only) and the guard (from
  `team.json` only), never its text.
- Off is enforced by the guard on every Agent call, not by the agent file.
- No new process for the hall, no network; the pane's new script answers by exit code only.
