## 3.6a: the data

- `plugin/team/team.mjs`: the strict schema takes `does` and `preset` and drops `kind` (version 2), checks 5 per guild,
  and `toolsOf()` reads the preset. The generator writes Dima's text inside its fixed frame and the standard rules
  after it. The upgrade from version 1 changes no tool any specialist has (a test runs it over the defaults and over
  a team with every v3.4 shape).
- `defaults.json`: the 8 specialists get their `does` text and preset, unchanged in what they do.
- Open: whether an agent file's `tools:` takes `Bash(npm test)` and `Bash(npm run check)` as patterns, which would make
  the third preset exact instead of a whole shell. The v3.4f finding says the engine has no pattern for `Agent(...)`;
  a no-login probe checks Bash before 3.6a decides. If it works, it is the preset's tools; if not, Bash as today.

## 3.6b: the API

- `POST /api/team` takes three more changes (`specialist-add`, `specialist-change`, `specialist-delete`) in
  `src/team/schema.ts`, mirrored in `team.mjs` (`team-page.test.ts` keeps them in step). Deleting one takes it out of
  every row; a specialist running at that moment finishes, and the next start is denied.
- `team-log.mjs`: "Specialist added: <name> (<guild>)", "Specialist changed: …", "Specialist deleted: …", names that
  pass the name rule only.

## 3.6c: the panel

- Built from the approved mockup only. Tabs as a `tablist`, cards and chips as real buttons, the skill menu as a menu
  button with arrow keys and Escape, focus kept on what you acted on, every save announced in the polite live region.
- Checked in Edge (Playwright, a fresh temporary profile, a real hall on a free port): every change through the keyboard
  alone, and the tab order. Narrator and how it looks are Dima's checklist.

## 3.6d: refreshing

- `plugin/hooks/team-check.mjs`: exit 0 when the team's `generator` is this plugin's, 6 when it is older, 4 when there
  is no team or it is broken; prints nothing. The pane runs it at session start and shows "Your team's specialist files
  are from an older plugin. Type /world-of-agents:setup-team-write to refresh them."
- `setup-team-write` on an existing team: rewrites the generated files and `generator` only, after checking the team
  as `readTeam()` does; it never changes `team.json`'s specialists, skills or texts. A test plants every field and
  compares before and after.

## Security notes

- Dima's text becomes part of an agent's prompt: it gets the skill text's refusals and flags, a size cap, and the
  standard rules after it. What limits a specialist is still its tools (from the preset only) and the guard (from
  `team.json` only), never its text.
- Only Dima changes the team: the one-time key, the cookie, the exact Origin; the guard and the template keep agents
  out of the team folder.
- No new process, no network; the pane's new script answers by exit code only.
