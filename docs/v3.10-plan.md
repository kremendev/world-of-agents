# v3.10.0: adding skills to the library, three ways

Plan only, from Dima's brief of 16 Nov ("PLAN, DON'T BUILD", part B), with his answers of the same day worked in. It
builds on v3.9.0's library (docs/v3.9-plan.md). Nothing here is built until he sends the approved Team page mockup, which
A and B share; Claude makes it in his review chat. A and B are two versions (my call, as the brief allowed): B opens the
network, so its review stays apart from A's move.

**In one line:** Dima adds a skill to the library from his own Claude skills on disk, from a GitHub link, or by pasting a
whole SKILL.md; all three end on one preview he approves, and what is saved is exactly the text he saw, with its source
and licence. The hall's first and only network use is one HTTPS GET to `raw.githubusercontent.com`, on his click.

## What the probes already settled (16 Nov)

1. **His Claude skills are on disk, in two places.**
   - Claude Code's own `~/.claude/skills/synced/<org>_<account>/<skill>/SKILL.md`: 22 skill folders here, no labels
     (an empty `.bucket-…` file beside them). `~/.claude/skills/<skill>/SKILL.md` is where personal skills go.
   - The desktop app's store, under its package folder:
     `%LOCALAPPDATA%\Claude-Data\claude_<package>\local-agent-mode-sessions\skills-plugin\<org>\<account>\skills\`, with
     a `manifest.json` whose entries say `creatorType`: `user` (7 here, the ones he uploaded) or `anthropic` (19). All 7
     of his are also in the synced folder above.
   - 9 of the app's 26 skill folders have `scripts/` or `references/` beside SKILL.md. The largest synced SKILL.md is
     42,544 bytes.

   So no export is needed. Dima's answer: the hall reads `~/.claude/skills` only, the synced folder included, and the
   app's manifest only for each skill's label.

2. **A long preloaded skill loads whole.** A subagent with a 40,267-character skill in `skills:` (Haiku, $0.008 with the
   baseline): its first turn held the whole body and it quoted the marker from the very last line. Its first turn was
   15,505 input tokens against 4,529 for the same agent without the skill: the skill cost about 10,976 tokens, **about one
   token per 3.7 characters** of English. That is the preview's estimate.
3. **The description never reaches a preloaded agent.** Claude Code strips the frontmatter: the agent saw no
   description at all and said so. A long description costs nothing per start; it only has to parse. A quoted,
   multi-sentence description with a colon and escaped quotes parsed (YAML 1.2 and 1.1, and Claude Code loaded the skill
   with no warning).
4. **The catalog Dima counted** (`davila7/claude-code-templates`, its file tree on 16 Nov, sizes only): 932 SKILL.md.
   Median 8,564 bytes; 46% fit today's 8,000; 72% fit 12,000; 87% fit 16,000; **93% fit 20,000**; 96% fit 24,000; the
   largest is 160,184. **515 of the 932 skill folders hold other files** beside SKILL.md.

## The three ways in

All three are Team page actions on Dima's click, through the hall's cookie and exact-Origin checks; no agent and no hook
can reach any of them.

1. **Your Claude skills.** The hall lists the SKILL.md files under `~/.claude/skills/` (his personal skills and the
   synced account skills), each with its source: **mine** where the app's manifest says `user` (and for a personal skill
   outside `synced/`), **built-in** where it says `anthropic`, and "not labelled" when the manifest can't be read; the
   manifest is read for those labels and nothing else. Read rules: only files named
   `SKILL.md`, at most three folders down; every path component `lstat`ed and skipped if it is a link or junction, and the
   real path must stay under the root; 64 KiB per file read at most; 200 files listed at most. Nothing is read until he
   presses the button, and only the one he picks goes to the preview.
2. **Add from GitHub.** He pastes a link; the hall fetches that one SKILL.md and nothing else.
   - The link must match one of three shapes, parsed into owner, repo, ref and path:
     - `https://github.com/<owner>/<repo>/blob/<ref>/<path>/SKILL.md`
     - `https://github.com/<owner>/<repo>/tree/<ref>/<path>` (the folder: `/SKILL.md` is added)
     - `https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>/SKILL.md`

     Owner: letters, digits and single hyphens,
     1 to 39. Repo: letters, digits, `.`, `_`, `-`, 1 to 100, never `.` or `..`. Ref: one such segment (a branch name with
     a slash isn't accepted: it can't be told from the path) or a 40-hex commit. Path: such segments, no `.` or `..`, at
     most 10, 300 characters in all. No query, no fragment, no `@`, no port, no other host. Anything else is refused with
     the pattern shown.

   - The request: `GET https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>` built from the parsed parts, the host
     a constant. No redirect followed (any 3xx is an error), 10 s timeout, the body read up to 128 KiB and refused past it,
     no cookies, no auth, a fixed User-Agent with nothing of Dima's in it. Only from the hall server; the page's CSP stays
     `connect-src 'self'`.
3. **Paste a whole SKILL.md**, header included, into a box on the Team page.

## The preview, the same for all three

- The whole text, line by line, with today's flags (links, command-like lines) and the notes' "instruction-like" flag.
- Every header field but `name` and `description` shown by name and dropped, with a warning for `allowed-tools` ("would
  have let tools run without asking") and `hooks` ("would have run commands").
- A warning when the text names files that don't come along: `scripts/`, `references/`, `assets/`, a relative path, or
  a command running one (`python scripts/fill.py`): "This skill mentions files that don't come along: …".
- The source (owner/repo, ref and path; or "your Claude skills" and which folder; or "pasted"), its `license` field as
  written, and the estimate: "about N tokens, read every time each specialist that has it starts", N the characters
  divided by 3.7, to the nearest hundred.
- **Add to library** and **Cancel**. Every skill is approved one at a time.

And on each specialist's page (Dima): its skills' total, in tokens, against the 40,000-character cap, so he sees what
every start of that specialist costs.

## Saved and refused

- Saved: exactly the text he saw, with source, ref, licence and the time, in `library.json` and `library/skills/<id>.md`.
  Never fetched again on its own.
- **Check for update** (GitHub skills only) fetches the same parsed link again and shows the differences, line by line;
  he accepts them or keeps what he has.
- Still refused, in every way in: a line starting with `` !` `` (an injected command) and hidden characters (every Cc
  but tab and line breaks, every Cf: bidi controls, zero-width characters, the BOM, the tag characters).
- Scripts and extra files never come along: only the one SKILL.md is ever read.

## The rules, revisited (since 3.6e quotes every frontmatter value)

The three caps are Dima's decision (16 Nov), as proposed.

| Rule                            | Today                                                                   | Decided                                                                                | Why                                                                                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A skill's description           | `LINE`: letters, digits, space, `.,()'&/-`, 200 chars (656 of 931 fail) | any single printable line, trimmed, no hidden characters, at most **1,024 characters** | Quoting made the narrow set unnecessary; it never reaches a preloaded agent (probe 3); 1,024 is the limit I remember for Anthropic's skill format, to confirm in 3.10a |
| A skill's text                  | 8,000 characters                                                        | **20,000 characters** (93% of the catalog fit; about 5,400 tokens)                     | Probe 2: 40,000 loads whole, so the cap is about cost                                                                                                                  |
| A specialist's preloaded skills | 5 skills                                                                | 5 skills **and 40,000 characters together** (about 10,800 tokens per start)            | Five 20,000-character skills would be 27,000 tokens on every start                                                                                                     |
| A skill's name                  | `LINE`, 60                                                              | unchanged                                                                              | it becomes the skill's name in our generator                                                                                                                           |

## README, security part

The warning against catalog installers (`npx claude-code-templates …` and the like) went out with v3.8.0 (3.8b, Dima's
answer), in "What it never does". This version only checks it still reads true.

## Security

- The hall's only network call, to one fixed host, from parsed parts, on a cookie-and-Origin-checked click. Tests pin
  that no other code path in the hall opens a connection, and that every refused link makes none.
- No redirect, a size cap and a timeout, so a slow or huge answer can't hold the hall.
- What's fetched is untrusted text: the same refusals and flags as a typed skill, shown whole before it's saved, saved
  exactly as shown.
- Reading `~/.claude/skills` is read-only, links never followed, size and count capped. That folder can hold secrets in
  other files; only SKILL.md is ever opened.
- Parsing a header (Dima: misreading a third-party header is a bigger risk than one dependency): the `yaml` package at
  exactly 2.9.1, today a dev dependency since 3.6e, moved to `dependencies`, still pinned exactly, bundled into the hall.
  Only after the size check; the core schema; unique keys; an alias limit of 5; never a custom tag, and a header that uses
  a tag of its own, or makes the parser warn, is refused whole.

## 3.10a: the probes (16 Nov, Claude Code 2.1.325)

The Team page mockup was approved the same day (Dima, in his review chat); this version builds to it.

1. **The 1,024-character description.** Anthropic's skill format says so: `description` "Must be non-empty, Maximum
   1,024 characters, Cannot contain XML tags"; `name` "Maximum 64 characters" of lowercase letters, digits and hyphens
   (platform.claude.com, Agent Skills overview). Claude Code itself is looser: a throwaway plugin with descriptions of
   1,000, 1,024, 1,025 and 1,100 characters loaded all four skills with no warning (no login, the debug log), and
   `claude plugin validate` passed it. So 1,024 is the format's limit, kept as decided. Our generated skills set no
   `disable-model-invocation`, but no World of Agents agent has the Skill tool, so a description still reaches no agent.
2. **The header fields the catalog uses.** 30 SKILL.md files spread through `davila7/claude-code-templates` (its file
   tree: 932 SKILL.md, the largest 160,184 bytes), fetched raw, parsed with `yaml` 2.9.1 (core schema, unique keys, an
   alias limit of 5): every one parsed. Keys: `name` and `description` 30, `metadata` 13 (author, version, tags,
   dependencies, source and such inside), `license` 5, `allowed-tools` 5 (one of them `Bash(dd-cli:*), Bash(mkdir:*)…`),
   `version`, `author`, `tags` and `dependencies` 2 each, `repo` 1; no `hooks`. One description was a literal block
   (`description: |`) with a line break, 352 characters: the check screen joins its lines with single spaces, and shows
   the result. 15 of the 30 mention `scripts/` or `references/`.
3. **The fetch.** Node's `fetch` with `redirect: 'manual'` against `raw.githubusercontent.com`: a file is 200
   `text/plain; charset=utf-8`, sent gzip, so `content-length` is the compressed size (10,628 for 29,886 bytes) and the
   cap counts decoded bytes as they arrive; the 160 KB skill stopped at 134,246 with the reader cancelled. A folder (a
   `tree` link without `/SKILL.md`), a missing file and a missing repository are each a plain 404 of 14 bytes. A renamed
   owner (`zeit/next.js`, now `vercel`) answered 200 at once, with no redirect, so a 3xx stays an error and an old name
   keeps working. Each answer came within 230 ms.
4. **The labels, and a change since the plan.** The app's manifest (`creatorType`) says `user` for Dima's 7 skills and
   `anthropic` for 19, as on 16 Nov's first look. New: the synced folder now has a `manifest.json` of its own, inside
   `~/.claude/skills`, whose `source` is `anthropic` or `anthropic-example` for the 15 built-in ones and `plugin` (with a
   `backingPluginId`) for Dima's 7. It agrees with the app's manifest on all 22. Built as decided (the app's manifest,
   for labels only); labelling from the synced one instead, which would keep every read inside `~/.claude/skills`, is a
   question for Dima. How soon the synced folder follows an upload or a delete on claude.ai needs his account: his list.

## 3.10b: the rules (built 16 Nov)

- `team.mjs`: `MAX_TEXT` 20,000; `isDescription()` for a library skill's description (one line, 1 to 1,024 characters,
  trimmed, no Cc, Cf, Zl, Zp or lone surrogate) and a license (200); `MAX_SPECIALIST_TEXT` 40,000, through
  `overCap()`: `changeProject()` checks this project's specialists and, for a changed text, every other project's
  before it writes anything, and `writeProjectTeam()` checks again. The refusal names who: "in blog, the Packer's skills
  would come to 40,001 characters, over 40,000". The shared team's rules are unchanged: it is only read.
- Sources: `github` {owner, repo, ref, path, license}, `claude` {label, file, license} and `pasted` {license}, each
  strict; `add-skill` keeps a source the hall gives and writes `written` otherwise. The page's schema mirrors all of it,
  and `team-page.test.ts` holds the two in step.
- The page: each specialist says "About N tokens every time it starts · X of 40,000 characters", with a 4 px bar, amber
  past 85%; "+ Add from library" leaves out a skill bigger than what's left, and says how many; the specialist form
  refuses skills over 40,000 together; the skill form takes the new description rule. A specialist with no skills costs 0
  tokens (it said 10).
- Eleven planted bugs, all caught once two tests were sharpened: a change in this project growing its own specialist
  past the cap was untested, and the form's own refusal had no test.

## 3.10c: the check (built 16 Nov)

- `yaml` 2.9.1 moved to `dependencies`, still exact; `npm audit` clean. Only the hall imports it.
- `server/skill-check.ts`, `checkSkillFile(raw)`: a file over 128 KiB or a header over 16 KiB is refused before
  anything is parsed; a byte order mark before the header is dropped (it is never saved); no header, or one that never
  ends, is refused. The header: `parseDocument` with the core schema, unique keys and no custom tags; any error or
  warning, any explicit tag (`!!str` too), a key that isn't a plain word, a header that isn't keys and values, and more
  than 5 aliases (`toJS`) refuse it whole. Kept: `name`, `description` and `license` as text, a description of several
  lines made one; a name or description that isn't text comes as nothing, for the check screen to ask for. Dropped and
  named: every other key, with `allowed-tools` "would have let tools run without asking" and `hooks` "would have run
  commands". The text after the header is trimmed and otherwise left alone: the page refuses and flags it with
  `checkText()`, and team.mjs checks it again when it is saved.
- `mentions()`: what the text names that won't come along, in order, each once, at most 12: `scripts/`,
  `references/`, `assets/` and the like, `./` and `../` paths, Markdown links to files, other `.md` files by name (not
  SKILL.md), and a script a command runs.
- The page: `skillLines()` flags a skill's line "overrides your rules?" (ignoring or bypassing rules, instructions, the
  guard or the prompt; without asking or approval; not telling the user; `.env`; sending something to an address, a
  webhook or a server); notes keep `noteLines()`'s instruction rule, and neither gets the other's flag. The Library tab
  and the skill form use it.
- Fifteen planted bugs; fourteen caught. The fifteenth, warnings ignored, can't be reached: inside our header (which ends
  at the first `---` after the opening one) every warning yaml 2.9.1 gives comes with a tag or an error, both refused on
  their own. It stays as a second lock.

## 3.10d: the three ways in, the hall's side (built 16 Nov)

The screens come with 3.10f, as the parts below say; this part is what the hall reads and keeps.

- `POST /api/team/skill` (`server/hall.ts`), with every control `POST /api/team` has (the page's exact Origin, the session
  cookie, JSON, a 1 MiB cap for a 128 KiB paste's JSON escapes, `skillAskSchema`), writes nothing. Its asks: `paste`,
  `claude-list`, `claude` (one file the list named), `github` (a link) and `recheck` (a library skill from GitHub, its
  kept link fetched again).
- Each SKILL.md read goes through `checkSkillFile()` and is kept in memory under 12 random bytes, the newest 10, bound to
  its project; a license that isn't one line of 200 characters refuses it. In `POST /api/team`, `take-skill` (the check's
  id, the library id, the name and description as Dima left them) and `update-skill` (the check's id, the skill's) save
  the hall's text and the source it found, never the page's; a check is taken once, never with a refusal, never from
  another project's session; an update needs a GitHub check of the skill's own owner, repository, ref and path, and
  keeps the license it found (`change-skill` in team.mjs takes an optional source for that). Check for update's hall side
  is built here; 3.10e keeps the page's: the differences, line by line, accept or keep.
- `server/claude-skills.ts`: the read rules above; a personal skill is "mine", a synced one what the app's manifest says
  (`user` mine, `anthropic` built-in), or "unlabelled"; how many were too big is counted for the screen.
- `server/github.ts`: `parseLink()` takes the three shapes, every part through team.mjs's segment rules; `fetchSkill()`
  makes the one GET as planned. Tests give a fake fetch and never reach GitHub.
- The bundle takes yaml's ES module build (an alias in `build-plugin-hall.ts`): its CommonJS build `require()`s `process`,
  which an ES module bundle can't, so the hall would throw at the first header, and it prints every token it reads when
  `LOG_TOKENS` or `LOG_STREAM` is set. `checkSkillFile()` parses with `logLevel: 'silent'`. `dropped` in skill-check.ts
  now has its type written out: `tests/` reaches it through hall.ts, in a config without `noUncheckedIndexedAccess`.
- Seventeen planted bugs, fifteen caught. Three tests were sharpened: the size-cap test is bounded (below), the fixture has
  a junction inside `~/.claude/skills` (its real path passes, so only the lstat leaves it out: `stat` for `lstat` was
  never tested), and an update is tried with GitHub checks of another folder and another ref (the old test used a pasted
  check, refused before the link was compared). Two can't be caught, second locks no input can reach: a `?` let through
  the link pattern (every part then meets the segment rule, which has no `?`), and `isSymbolicLink()` dropped (`lstat`
  never calls a link a folder or a file: a junction here is a link, not a folder).
- **The crash (16 Nov).** The first run of the plants marked "no size cap on GitHub" missed with `Tests (31)`: Vitest's
  summary with no counts, 31 tests collected and none reported, because the test file's run died. Its test fed
  `fetchSkill()` an endless stream; with the cap planted out, the read never ended. Such a stream answers at once, so
  it is read in microtasks alone and no timer, the test's timeout included, gets a turn, and its pieces live outside the
  V8 heap, where `--max-old-space-size` doesn't reach (both checked with a bounded stream). Rerunning that plant by hand,
  with `sed -i` in the working tree, ran the PC out of memory and VS Code with it, twice; the backup was put back each
  time. Now the test's stream sends twice the cap, then closes, waits a turn between pieces, has a 5 s timeout and fails
  with one short line; with the cap planted out it fails in 249 ms. The plants run in a throwaway worktree, with a 512 MB
  heap and a timeout that ends the whole process tree, and a run that dies or prints no summary counts as FAILED, never
  as caught (Dima's rules, in CLAUDE.md's Testing notes).
