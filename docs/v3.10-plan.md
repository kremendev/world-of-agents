# v3.10.0: adding skills to the library, three ways

Plan only, from Dima's brief of 16 Nov ("PLAN, DON'T BUILD", part B), with his answers of the same day worked in. It
builds on v3.9.0's library (docs/v3.9-plan.md). Nothing here is built until he sends the approved Team page mockup, which
A and B share; Claude makes it in his review chat. A and B are two versions (my call, as the brief allowed): B opens the
network, so its review stays apart from A's move.

**In one line:** Dima adds a skill to the library from his own Claude skills on disk, from a GitHub link, or by pasting a
whole SKILL.md; all three end on one preview he approves, and what is saved is exactly the text he saw, with its source
and licence. The hall's first and only network use is one HTTPS GET to `raw.githubusercontent.com`, on his click.

## What the probes already settled (16 Nov)

1. **His Claude skills are on disk, in two places.**
   - Claude Code's own `~/.claude/skills/synced/<org>_<account>/<skill>/SKILL.md`: 22 skill folders here, no labels
     (an empty `.bucket-…` file beside them). `~/.claude/skills/<skill>/SKILL.md` is where personal skills go.
   - The desktop app's store, under its package folder:
     `%LOCALAPPDATA%\Claude-Data\claude_<package>\local-agent-mode-sessions\skills-plugin\<org>\<account>\skills\`, with
     a `manifest.json` whose entries say `creatorType`: `user` (7 here, the ones he uploaded) or `anthropic` (19). All 7
     of his are also in the synced folder above.
   - 9 of the app's 26 skill folders have `scripts/` or `references/` beside SKILL.md. The largest synced SKILL.md is
     42,544 bytes.

   So no export is needed. Dima's answer: the hall reads `~/.claude/skills` only, the synced folder included, and the
   app's manifest only for each skill's label.

2. **A long preloaded skill loads whole.** A subagent with a 40,267-character skill in `skills:` (Haiku, $0.008 with the
   baseline): its first turn held the whole body and it quoted the marker from the very last line. Its first turn was
   15,505 input tokens against 4,529 for the same agent without the skill: the skill cost about 10,976 tokens, **about one
   token per 3.7 characters** of English. That is the preview's estimate.
3. **The description never reaches a preloaded agent.** Claude Code strips the frontmatter: the agent saw no
   description at all and said so. A long description costs nothing per start; it only has to parse. A quoted,
   multi-sentence description with a colon and escaped quotes parsed (YAML 1.2 and 1.1, and Claude Code loaded the skill
   with no warning).
4. **The catalog Dima counted** (`davila7/claude-code-templates`, its file tree on 16 Nov, sizes only): 932 SKILL.md.
   Median 8,564 bytes; 46% fit today's 8,000; 72% fit 12,000; 87% fit 16,000; **93% fit 20,000**; 96% fit 24,000; the
   largest is 160,184. **515 of the 932 skill folders hold other files** beside SKILL.md.

## The three ways in

All three are Team page actions on Dima's click, through the hall's cookie and exact-Origin checks; no agent and no hook
can reach any of them.

1. **Your Claude skills.** The hall lists the SKILL.md files under `~/.claude/skills/` (his personal skills and the
   synced account skills), each with its source: **mine** where the app's manifest says `user` (and for a personal skill
   outside `synced/`), **built-in** where it says `anthropic`, and "not labelled" when the manifest can't be read; the
   manifest is read for those labels and nothing else. Read rules: only files named
   `SKILL.md`, at most three folders down; every path component `lstat`ed and skipped if it is a link or junction, and the
   real path must stay under the root; 64 KiB per file read at most; 200 files listed at most. Nothing is read until he
   presses the button, and only the one he picks goes to the preview.
2. **Add from GitHub.** He pastes a link; the hall fetches that one SKILL.md and nothing else.
   - The link must match one of three shapes, parsed into owner, repo, ref and path:
     - `https://github.com/<owner>/<repo>/blob/<ref>/<path>/SKILL.md`
     - `https://github.com/<owner>/<repo>/tree/<ref>/<path>` (the folder: `/SKILL.md` is added)
     - `https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>/SKILL.md`

     Owner: letters, digits and single hyphens,
     1 to 39. Repo: letters, digits, `.`, `_`, `-`, 1 to 100, never `.` or `..`. Ref: one such segment (a branch name with
     a slash isn't accepted: it can't be told from the path) or a 40-hex commit. Path: such segments, no `.` or `..`, at
     most 10, 300 characters in all. No query, no fragment, no `@`, no port, no other host. Anything else is refused with
     the pattern shown.

   - The request: `GET https://raw.githubusercontent.com/<owner>/<repo>/<ref>/<path>` built from the parsed parts, the host
     a constant. No redirect followed (any 3xx is an error), 10 s timeout, the body read up to 128 KiB and refused past it,
     no cookies, no auth, a fixed User-Agent with nothing of Dima's in it. Only from the hall server; the page's CSP stays
     `connect-src 'self'`.
3. **Paste a whole SKILL.md**, header included, into a box on the Team page.

## The preview, the same for all three

- The whole text, line by line, with today's flags (links, command-like lines) and the notes' "instruction-like" flag.
- Every header field but `name` and `description` shown by name and dropped, with a warning for `allowed-tools` ("would
  have let tools run without asking") and `hooks` ("would have run commands").
- A warning when the text names files that don't come along: `scripts/`, `references/`, `assets/`, a relative path, or
  a command running one (`python scripts/fill.py`): "This skill mentions files that don't come along: …".
- The source (owner/repo, ref and path; or "your Claude skills" and which folder; or "pasted"), its `license` field as
  written, and the estimate: "about N tokens, read every time each specialist that has it starts", N the characters
  divided by 3.7, to the nearest hundred.
- **Add to library** and **Cancel**. Every skill is approved one at a time.

And on each specialist's page (Dima): its skills' total, in tokens, against the 40,000-character cap, so he sees what
every start of that specialist costs.

## Saved and refused

- Saved: exactly the text he saw, with source, ref, licence and the time, in `library.json` and `library/skills/<id>.md`.
  Never fetched again on its own.
- **Check for update** (GitHub skills only) fetches the same parsed link again and shows the differences, line by line;
  he accepts them or keeps what he has.
- Still refused, in every way in: a line starting with `` !` `` (an injected command) and hidden characters (every Cc
  but tab and line breaks, every Cf: bidi controls, zero-width characters, the BOM, the tag characters).
- Scripts and extra files never come along: only the one SKILL.md is ever read.

## The rules, revisited (since 3.6e quotes every frontmatter value)

The three caps are Dima's decision (16 Nov), as proposed.

| Rule                            | Today                                                                   | Decided                                                                                | Why                                                                                                                                                                    |
| ------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A skill's description           | `LINE`: letters, digits, space, `.,()'&/-`, 200 chars (656 of 931 fail) | any single printable line, trimmed, no hidden characters, at most **1,024 characters** | Quoting made the narrow set unnecessary; it never reaches a preloaded agent (probe 3); 1,024 is the limit I remember for Anthropic's skill format, to confirm in 3.10a |
| A skill's text                  | 8,000 characters                                                        | **20,000 characters** (93% of the catalog fit; about 5,400 tokens)                     | Probe 2: 40,000 loads whole, so the cap is about cost                                                                                                                  |
| A specialist's preloaded skills | 5 skills                                                                | 5 skills **and 40,000 characters together** (about 10,800 tokens per start)            | Five 20,000-character skills would be 27,000 tokens on every start                                                                                                     |
| A skill's name                  | `LINE`, 60                                                              | unchanged                                                                              | it becomes the skill's name in our generator                                                                                                                           |

## README, security part

The warning against catalog installers (`npx claude-code-templates …` and the like) went out with v3.8.0 (3.8b, Dima's
answer), in "What it never does". This version only checks it still reads true.

## Security

- The hall's only network call, to one fixed host, from parsed parts, on a cookie-and-Origin-checked click. Tests pin
  that no other code path in the hall opens a connection, and that every refused link makes none.
- No redirect, a size cap and a timeout, so a slow or huge answer can't hold the hall.
- What's fetched is untrusted text: the same refusals and flags as a typed skill, shown whole before it's saved, saved
  exactly as shown.
- Reading `~/.claude/skills` is read-only, links never followed, size and count capped. That folder can hold secrets in
  other files; only SKILL.md is ever opened.
- Parsing a header (Dima: misreading a third-party header is a bigger risk than one dependency): the `yaml` package at
  exactly 2.9.1, today a dev dependency since 3.6e, moved to `dependencies`, still pinned exactly, bundled into the hall.
  Only after the size check; the core schema; unique keys; an alias limit of 5; never a custom tag, and a header that uses
  a tag of its own, or makes the parser warn, is refused whole.
