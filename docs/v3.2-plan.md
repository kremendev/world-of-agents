## What was checked on 11 Nov

- **Per-turn usage exists.** `turn.complete`'s input carries `usage?: TurnUsage`: the turn's real requests' four token counts
  (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`), summed, and the `model` of the
  last response that counted; absent on an interrupt or an API error. "Every hook hears an agent's end": subagent turns come
  with their `agentId` (the engine's types for 2.1.319, `tools/claude-code-types/index.d.ts`).
- **The classic `Stop` and `SubagentStop` hooks carry no usage** (same types), so the hall can't count on its own from
  `send.mjs`'s posts without reading transcript files, which it never does.
- **The mods API has nothing for past sessions.** `$.session.messages()` reads the current session only; nothing lists
  older ones. Only Claude Code's transcript files hold them (`~/.claude/projects/<project>/<session>.jsonl`, and
  `<session>/subagents/*.jsonl`; seen in the 3.1b terminal run, each assistant entry with `message.model` and
  `message.usage`).
- **`$.store`**: the plugin's own key-value store, kept between sessions, JSON only, 4 MiB in all; `get`, `set` and `delete`,
  no atomic update.
- **Prices** (platform.claude.com/docs/en/about-claude/pricing, read 11 Nov), per million tokens, input / 5-minute cache
  write / cache hit / output: Fable 5.2 $8 / $10 / $0.20 / $40; Opus 5.5 $4 / $5 / $0.20 / $20; Sonnet 5.5 $2 / $2.50 /
  $0.10 / $10; Haiku 5.5 (prompts up to 100,000 tokens) $0.10 / $0.125 / $0.01 / $0.50. Fast mode is priced higher (Opus 5.5
  $8 / $40) and Haiku 5.5 over 100,000 tokens too; the usage counts say neither.

## 3.2a: the live ledger in the mod

- `plugin/hooks/mod/ledger.ts` (new): the price table with its date and source; `addTurn(ledger, usage, now)` (pure: the
  counts per model, a model id of 1 to 64 characters of `a-z 0-9 . _ -` only, at most 32 models, each count capped);
  `valueOf(ledger)` (whole cents, and the tokens of models with no price); `ledgerLine(ledger)` for the pane.
- `register.tsx`: on every `turn.complete` with `usage`, read `ledger` from `$.store`, add, write back, then the view. A store
  that throws loses that turn's count and nothing else (quietly). At session start the view gets the kept total.
- `types.d.ts`: `PaneView.ledger` (the totals the pane draws), shape tag `view-6`.
- `pane.tsx`: a "This PC" line under the usage: "This PC since 11 Nov: 3.2M tokens in, 180K out, about $12.40 at API
  prices (11 Nov 2026)." and, when some model had no price, "Not priced: 40K tokens of <model id>". Model ids are engine
  data, not agent text, and are drawn as plain `Text` anyway.
- Tests: `ledger.test.ts` (Vitest, under `tests/plugin/`: the sums, caps, rounding, unknown models, a bad model id dropped);
  kit tests in `register.test.tsx` (a Lead turn and a subagent turn both count, a turn with no usage doesn't, a store that
  throws costs nothing else, the pane line); `mod.test.ts` unchanged (no new `$` call: `store.get` and `store.set` are on
  the surface already).

## 3.2b: the total in the hall's page

**Built 11 Nov.** The script is `ledger-post.mjs`, with 3.1f's run check (real paths, never a name). The ledger reaches the page as a named SSE event (`ledger`) through `parseLedger()`, not as an office
event: it changes nothing in the office. `process.run` takes `stdin`, not `input`, so `mod.test.ts` pins `stdin:` to
that one line in `hall.ts`.

- `plugin/hooks/ledger-post.mjs` (new, with `.d.mts`): reads stdin (capped at 4 KB), parses the strict totals shape, checks
  the hall with `hallKnowsToken()` and posts to `/api/ledger` with the Bearer token, no redirect, capped answer. Prints
  nothing; exit 0 always.
- `plugin/hooks/mod/ledger.ts`: `sendLedger($, totals)`: `$.process.run` of exactly `node <plugin>/hooks/ledger-post.mjs`,
  cwd the plugin's folder, the totals as `input`. Run after each of the Lead's turns and at session start, only while the
  pane's hall is `running`. `mod.test.ts`'s pins of where `process.run` and `input` appear grow by this one place.
- `server/hall.ts`: `POST /api/ledger` with `authorized()`, a 4 KB body cap and `ledgerSchema`; the latest total is kept in
  memory and sent to every page after its replay (and to open pages at once), never stored in the 500-event replay.
- `src/events/schema.ts`: a `ledger` event (strict: `since`, `tokensIn`, `tokensOut`, `cents`, `pricedOn`, `unpriced`),
  through `parseEvent()` like every event. It changes nothing in the office.
- `src/live/useLiveHall.ts`: keeps the last ledger event; `App.tsx` shows the header line in Live.
- `npm run build:plugin-hall`.
- Tests: `tests/plugin/ledger-send.test.ts` (real servers on free ports, as `handshake.test.ts`: posts only after the
  handshake, never to a stranger, nothing printed, bad input posts nothing); `server/hall.test.ts` (token, Host, Origin, size,
  schema, kept in memory, sent after a replay); `schema.test.ts`; `App.live.test.tsx` (the header line, Live only);
  `install.test.ts`'s pins of the built hall if they list routes.

## 3.2c: past sessions

**Built 12 Nov, Dima's L7.** What it does, as built:

- `plugin/hooks/ledger-past.mjs` reads `{"before": <ms>}` on stdin (exactly that), finds `<config>/projects/<project>/*.jsonl`
  and `<project>/<session>/subagents/*.jsonl` (`CLAUDE_CONFIG_DIR` when set, else `~/.claude`), never through a link (a
  junction on Windows included), and parses only the lines that could be assistant responses with usage. A response
  spans several lines with one `message.id` (8,547 lines held 2,786 responses on this PC, 12 Nov; each id's usage the same
  on every line), so it counts each id once, across files too. Entries at or after the cut-off are the live ledger's.
  A response with four zero counts (Claude Code's `<synthetic>` error stand-ins) is no turn. It prints one line,
  `{"since", "models"}`, whole numbers per model id (others as `other`, at most 32), and exits 0; on stdin it doesn't
  take, nothing and exit 1. 196 MB of transcripts took a few seconds; the mod waits up to 120 s.
- The pane: a "Count past sessions" button under the "This PC" line, with what it reads. Pressed: one count at a time,
  the cut-off is the live ledger's `since` (now, if nothing was counted yet). `pastOf()` keeps the output only when it
  is exactly a ledger, at most 8 KiB, all of it before the cut-off, from an exit 0 that wasn't cut short; anything else is
  dropped whole and the pane says "Couldn't count past sessions." with the button again. Kept: `ledger-past` in
  `$.store` (`since`, `models`, `before`, `counted`), read back by `readPast()` as strictly. The "This PC" line is then
  one total from the earliest past session, with "Includes past sessions before <cut-off>, counted on <date>." under it,
  and the hall's header gets the same total.
- Tests: `tests/plugin/ledger-past.test.ts` plants transcripts full of secrets (in text, paths, a model id, the usage's
  other fields) and checks the output is exactly the expected numbers and holds none of them; the kit tests press the
  button, pin the command, its cwd and stdin, and run 13 bad outputs, each dropped whole with nothing stored. Planted
  bugs: 19, all caught (four only after their tests were sharpened).

The draft, before the decision:

The script either way: `plugin/hooks/ledger-backfill.mjs` walks `~/.claude/projects/*/` (`*.jsonl` and
`*/subagents/*.jsonl`), reads each line as JSON and keeps only `message.model` and the four `message.usage` counts of
assistant entries dated before the ledger's `since`, so nothing is counted twice. It never keeps a line, a path or any text:
a test plants transcripts full of secrets and checks its output and anything stored hold none. With A, the mod runs it on
the pane's "Count my past sessions" button once, parses its output strictly and adds it to the total as "past sessions,
counted on <date>". With B, it posts the totals to the hall instead.

## Risks

- **The value is an estimate**, and the pane says "about": cache writes priced at 5 minutes, no fast mode, Haiku's long-prompt
  price never used. It is a number for the desktop-app question (brief, "Later: an own desktop app"), not a bill.
- **It counts only where the mod runs.** Claude Code sessions without the plugin, claude.ai, the phone and other PCs share the
  plan and aren't counted; claude.ai/settings/usage is the full picture, as the brief says.
- **One more process per Lead turn** (L9), about 50 ms of Node, only while the hall runs.
- **A model the table doesn't know** (a new release): its tokens are counted, unpriced, until the table is updated.
