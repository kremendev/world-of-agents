> **Warning: install from a terminal, not the desktop app's Plugins screen.** On 11 Nov 2026 the desktop app's Plugins screen (app 5.1231) asked for no scope and installed World of Agents for every project. Then every session on that PC starts as the Lead/PM, runs the guard (which denies Claude Code's built-in agents) and reports to the hall. Install it per project instead, in the project folder:
>
> ```bash
> claude plugin install world-of-agents@world-of-agents --scope local
> ```
>
> Then run `claude plugin list`: no `world-of-agents` entry may say `Scope: user`. If one does, run `claude plugin uninstall world-of-agents@world-of-agents --scope user` and install it again in each project. The [README on main](https://github.com/kremendev/world-of-agents/blob/main/README.md#install-as-a-plugin) has the corrected steps.

The team moves into the Claude desktop app. Installed as a plugin in one project, World of Agents now guards which agents may start, sets the project up when you ask it to, shows the team in a pane beside the conversation, starts its own hall and tells you out loud when it needs you.

## What's new

- **The guard.** A hook before every agent start and every Bash or PowerShell command. It can only deny, never allow, so your approval prompt still decides. Only the Lead starts agents, and only the four others. A shell command that names a `.env` or `.envrc` file is denied too; that rule is best effort. A call the guard can't read is denied, and a guard that crashes or hangs blocks the call.
- **The setup skills.** `/world-of-agents:setup-project` shows, and `/world-of-agents:setup-project-write` writes, the project's `.claude/settings.local.json`: Manual mode, subagent depth 2, `npm test` and `npm run check` without asking, and denies for `.env` files and `git push`, plus a `.gitignore` line for that file. Only you can start them, and Claude Code runs a fixed script for both. A second run changes nothing. A file set up by an earlier template is upgraded, and every other setting in it stays as it is. Anything else stops and names the settings, never their values.
- **The team pane.** Beside the conversation: the five agents with their state and task, who waits for your approval, a warning in Auto, Bypass permissions and Accept edits, context and plan limits, three preset prompts and "Open hall". It only watches. It answers no tool call, permission check or agent start, and a preset only puts its text in your prompt box for you to send.
- **The hall starts itself.** The plugin carries a prebuilt hall: the page and one server file that needs nothing but Node, so there is no clone and no `npm install`. The pane checks for Node, starts the hall when nothing holds port 4319, and shows "Open hall" only once the hall has proved it holds the token.
- **The voice (Windows).** "Backend dev needs your approval." when a permission dialog opens, and "The team is done." with the first sentence of the Lead's answer once every run is over. It uses Windows' own speech synthesizer through a fixed script, with the text on stdin. **Mute voice** keeps it quiet in later sessions too.
- **Hall fixes.**
  - The Lead's answer stays in the feed when the desktop app picks the session up in a fresh process.
  - A speech bubble shows a message's first sentence as plain text, at most 90 characters, for 4 s plus 60 ms per character, at most 10 s, and an agent's next bubble waits for the one it shows. It never shows while its agent walks: it waits until the agent stops.
  - The activity feed gets the whole of each agent's report and of the Lead's answer, up to 20,000 characters. A long message shows cut: "Show all" opens the whole text, which you can select and copy.
  - Messages to you, approval waits and failures stand out in the feed with a border and a label ("To you", "Needs you", "Failed"), decided by the kind of event, never by what the text says.
  - Agents hurry when work starts or ends mid-walk. An agent whose work ends right after it sat down stays at its desk for 3 s, so you see it work.
  - A Markdown link in agent text shows as its text alone, never as a link.
  - The Reviewer reports only the checks it ran with its own tools.
  - The bundled hall server is 210 KB, down from 779 KB.

## What changed

- **The guard denies Claude Code's built-in agents.** With the plugin on, an agent start outside the team's table is denied, whoever asks: `Explore`, `Plan`, `general-purpose`, `claude-code-guide`, `statusline-setup`, any other agent, and any start by a subagent. v2 had no such check. This change in behaviour is why this is a major version. To use those agents in a project, turn the plugin off there.
- **More of the agents' text reaches the hall.** An agent's last message and the Lead's answer go to the hall on 127.0.0.1 whole, up to 20,000 characters, instead of their first 200. They are scrubbed as before (your home folder becomes `~`, anything shaped like a key `[redacted]`), and they are the agents' own words, so they can quote code or a command.
- **Node.js is needed wherever the plugin is on.** The guard fails closed: without Node, every agent start and every Bash or PowerShell command is blocked with `hook error: … Executable not found in $PATH: "node"`.
- **Claude Code 2.1.299 or later.** Older versions refuse the team pane.

## Requirements

- Claude Code 2.1.299 or later: the CLI, or the desktop app's Code tab. 2.1.299, 2.1.301, 2.1.307 and 2.1.319 pass the pane's own tests and validation, a session on 2.1.299 starts the hall, and the desktop app was checked with its engine at 2.1.317. 2.1.295 and 2.1.296 refuse the pane.
- Node.js 20.19 or later on PATH.
- Tested on Windows 11 only. On Windows, `woa` and the setup skills need Git Bash (it comes with Git for Windows): Claude Code runs the skills' fixed command through it, and nobody has tried them without it. The voice speaks on Windows only.

## Known limits

- In the desktop app, the setup's Manual reached a new session only in a git repository in our tests; in a folder without git the app used your own default mode. A mode you pick in the selector also sticks to that folder and wins over the file. Check the selector in the first new session after the setup, and if it doesn't say Manual, pick Manual once: the app remembers it for that folder. The pane warns in the modes that don't ask first.
- The hall lives with the session that started it. When that session closes, the plugin reloads, or the desktop app moves the session to a fresh process, the hall can go with it. The next Lead turn starts a new one, and the page says "Hall restarted" and remembers nothing from before. A later version plans a hall that runs on its own and stops itself after about 30 idle minutes.
- The setup skills put the plugin's path in single quotes. One apostrophe in it makes them fail safely. Two balance the quotes again, so the shell reads the text between them unquoted, and a `$(...)` there would run. Only the names of your own folders reach that path, never a project's or the conversation's.
- The `.env` rules are best effort. They stop accidents and lazy prompt injection, not someone set on getting around them.
- Claude Code has no sandbox on native Windows: commands run with your rights, and your approval is the guard.
- The hall follows one session at a time, on port 4319.
- An "Always allow" click in a set-up project adds a rule to its settings, and the next setup upgrade then stops and names `permissions.allow`. It writes nothing. v3.0.1 is planned to keep such rules through the upgrade.
- Where an organization's managed settings turn on `allowManagedHooksOnly`, a plugin you install yourself loads no hooks: the agents load, but with no guard, no team pane and no reports to the hall. That comes from Claude Code's own reference and hasn't been tested.

## Updating from v2

In a terminal. Adding the marketplace again with a new tag is refused, and removing it uninstalls the plugin, so install it again in each project that had it:

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.0.0
claude plugin install world-of-agents@world-of-agents --scope local   # in the project folder
```

Then type `/world-of-agents:setup-project` in each project. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.0.0/README.md).
