The project's setup now names the Lead/PM as the main agent, and the two warnings Claude Code 2.1.325 shows in every set-up project are gone.

## What changed

- **The setup names the Lead.** Until now the plugin's own settings made the Lead/PM the main agent. Claude Code 2.1.325 warns that a plugin doing that will stop working, so the plugin sets nothing any more: the project setup writes `"agent": "world-of-agents:lead"` into the project's `.claude/settings.local.json` with the rest of its settings (template version 4). Switch the plugin off or remove it, and that setting names an agent that isn't loaded: Claude Code starts the session as usual. `woa` passes `--agent` as before.
- **One rule less.** Template 4 drops `Write(~/.world-of-agents/**)`, which Claude Code said matches nothing: its file checks use `Edit` rules, and `Edit(~/.world-of-agents/**)` stops the Write tool in that folder too (checked with a real run). The guard still denies every edit there, from any agent.
- **A session that isn't the Lead is told why.** In a project whose setup isn't written yet, a session starts as plain Claude Code. The guard has always denied such a session's agent starts and file edits; now its reason says so and names the setup.
- **A user-scope install no longer makes every session the Lead,** but it is still wrong: the plugin's hooks run in every project, and the guard leaves no other session able to edit. Keep installs at local scope.
- **`woa` lets guild leads start their specialists.** It set the subagent depth to 1, a setting from v2, and at depth 1 Claude Code takes the Agent tool away from every subagent, so under `woa` no specialist could ever start. It now sets 2, as the project setup does, and a test holds the two together.
- **Don't run catalog installers in a set-up project.** The README now says why: an installer such as `npx claude-code-templates …` writes hooks and settings that can skip the permission prompts and undercut the guard, and the team can't use what it adds. Add a skill on the Team page instead.

## Updating from v3.7.0

In a terminal (Git Bash):

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.8.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then, in each project, type `/world-of-agents:setup-project-write`. It upgrades the settings from version 3 to version 4: it removes the deny rule `Write(~/.world-of-agents/**)`, sets `agent`, and keeps every rule you added. Start a new session afterwards: the Lead takes over from there. Until you do, the project's sessions are plain Claude Code. If you already added `"agent": "world-of-agents:lead"` yourself, the upgrade still recognises the file.

The v3.7.0 hall gives way to the new one at your next message, and your team needs nothing: no file the plugin makes from it changed.

Claude Code 2.1.312 or later (the project's `agent` was checked on 2.1.318 and 2.1.325) and Node.js 20.19 or later. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.8.0/README.md).
