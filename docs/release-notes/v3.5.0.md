The hall and the rules: a hall that runs on its own and stops itself, each session's activity kept, and the check run by every agent with a shell, last and exactly.

## New

- **A hall that stops itself.** The pane starts the hall with no window, on its own: closing the session that started it, or reloading the plugin, leaves it running, so every session in every project on this PC shares it. It stops itself after 30 minutes with no agent activity and no hall page open, and the pane starts it again at your next message. The desktop app keeps every process it starts in its own job, so quitting the app may stop the hall too.
- **A newer plugin replaces an older hall.** Two installs on one PC share the hall's port and token. From now on, a newer plugin asks an older hall (3.5.0 or later) to stop through the hall's own API, with the token, before it starts its own; never the other way round, and never by ending a process. A hall from before 3.5.0 can't be asked, so the pane still says "An older hall (vX) is running. Close your other sessions, here and in other projects." A newer hall than your plugin is never stopped: the pane says "Update World of Agents in this project to use it."
- **Each session's activity, kept.** The hall keeps the last three sessions' runs in memory, never on disk, up to 500 events each. Going back to a session (typing there, or resuming it) shows its run as it was, with what its agents did meanwhile, in one go: nothing is read out again, and the page doesn't say "Hall restarted".
- **The check, always, and exactly.** The Frontend dev, the Backend dev and every specialist with a shell now run `npm run check` themselves as their last step, even for a small change and even when someone runs it after them, and never `cd` first or chain anything onto it: their commands already run in the project folder, and `cd <project> && npm run check` is not the command the setup lets run without asking.

## Under the hood

- TypeScript 6.0.3, typescript-eslint 8.72.2 and ESLint 10.15.0, pinned exactly. `npm audit` is clean: the one advisory (`minimatch` before 11.0.1, through typescript-eslint) is fixed with an override until typescript-eslint takes the fixed `minimatch` itself.

## Updating from v3.4.0

In a terminal (Git Bash):

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.5.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then close every Claude Code session once: the v3.4.0 hall lives with the session that started it, and it is the last one that does. The next message starts the new hall.

Your team's specialist files were written by v3.4.0 and don't have the new check rules yet. Any save in the Team panel (**Change skills** in the pane) writes them again from your team, your skills and assignments unchanged: for example, give a skill to a specialist and take it away again. v3.6.0 will do this on its own after an update.

Claude Code 2.1.312 or later and Node.js 20.19 or later, as in v3.4.0. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.5.0/README.md).
