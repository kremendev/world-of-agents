Guilds and skills. **Read "Updating" first: after this upgrade no agent starts until the team exists.**

## New

- **Guilds of specialists.** The Designer, the Frontend dev, the Backend dev and the Reviewer now lead guilds, and each can hand focused work to its own specialists: React designer and Motion designer; React dev and Test writer; API dev and Database dev; Security warden and QA tester. Each specialist preloads a few short skills (accessibility, design tokens, Vitest, validation and auth, OWASP checks and the like). The Lead still talks to you and hands work to the guild leads. Ask for a specialist by name ("Have the React dev …") and the Lead passes that on; a guild lead also hands a piece to a specialist when it is clearly that specialist's area and more than a small change, and keeps small changes itself. Specialists that edit and have a shell end each task by running `npm run check` and report whether it passed, as the devs do; both run it exactly as written, with nothing added (a `--prefix` or a path would make Claude Code ask you), and never chained. The Designer, like the devs, and every specialist that edits change only the files their task names and leave no backup copies.
- **The team lives outside your projects.** `/world-of-agents:setup-team` shows, and `/world-of-agents:setup-team-write` creates, `~/.world-of-agents/team`: a small local plugin (`woa-team`) that holds the specialists and their skills as data. You install it once per project, like the main plugin, and every project shares it. The plugin writes that folder only from its own checked data; a skill is text only, and a line that Claude Code would run as a command is refused.
- **Who may start whom is read from the team.** The guard lets each guild lead start its own guild's specialists and nobody else's; specialists start nobody. If the team is missing or broken, the guard lets no agent start at all, and says to run `/world-of-agents:setup-team`. The Lead's own list of agents it may start is gone: Claude Code applied it to the whole session, so the guild leads could never see their specialists. The guard alone now decides who starts whom, deny-only and fail-closed; with hooks turned off (`disableAllHooks`), nothing limits it.
- **The team is yours alone.** The project setup's new version keeps the agents' file tools out of `~/.world-of-agents` (where the hall's token lives too), and the guard denies a shell command that names that folder (best effort, like the `.env` rule). The guard also denies any agent's Edit or Write into `~/.world-of-agents`, in every project, whether or not you ran the setup there. It checks the path as written and where it really lands, so a link, a junction or a Windows short name (`WORLD-~1`) that leads into the folder is caught too.
- **Change skills from the hall.** Press **Change skills** in the team pane: it makes a one-time key, hands it to the hall through a small fixed script, and shows a link to the hall for one minute. The hall's page takes the key out of the address bar at once and swaps it, once, for a cookie no script can read and no other site can send. Its **Team** panel then adds, changes and deletes skills and gives them to specialists or takes them away, five at most each. Before anything is saved you see the whole text, with links and command-like lines marked; a line Claude Code would run as a command, and invisible characters, are refused. Every change shows as a line in the pane: the time, what changed, and names. A link opened twice says "This link was already used. Open the hall again from the pane."
- **In the hall and the pane.** A guild lead's name plate shows its specialists at work ("Frontend dev + React dev"), and the pane lists them under their lead. No new sprites yet: those wait for a design round.

## Not yet

- **Adding, changing and deleting specialists** comes in v3.5.0, through the same Team panel.
- **Agent memory is off** for every agent: notes an agent writes unasked are a place where a hijacked agent plants instructions it reads again next session. The guard denies any agent's write into an agent memory folder (`.claude/agent-memory-local`, `.claude/agent-memory` or `~/.claude/agent-memory`) and says so. A later version lets an agent propose a note that you approve with a button; nothing is written without you.

## Known limit

- **The editor's link is briefly visible in the browser's command line** when the desktop app opens it, and stays in a browser process started for it until that closes. It works once and for one minute, so anything that reads it after you opened it gets nothing.

## Updating from v3.3.0

In a terminal (Git Bash). The plugin, as before:

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.4.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then, in a session in any project: `/world-of-agents:setup-team`, then `/world-of-agents:setup-team-write`. It prints the commands that add the team to a project:

```bash
claude plugin marketplace add ~/.world-of-agents                     # once on this PC
claude plugin install woa-team@woa-local --scope local                # in each project folder
```

Then `/world-of-agents:setup-project` in each project: it upgrades the settings to the template's version 3, which adds the three `~/.world-of-agents` denies. `/world-of-agents:setup-project-write` writes it. Run `/reload-plugins` or start a new session.

Claude Code 2.1.312 or later and Node.js 20.19 or later, as in v3.3.0. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.4.0/README.md).
