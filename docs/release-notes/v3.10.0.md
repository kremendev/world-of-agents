A team of its own for each project, one skill library for the PC, and three new ways to add a skill to it: from your own Claude skills, from a GitHub link, or by pasting a SKILL.md, each checked on one screen and saved exactly as you saw it. v3.9.0 was never released on its own: everything since v3.8.0 is here.

## A team per project, one library

- **A team per project.** Each project now has its own specialists, its own switches and its own notes. A project's team lives in `~/.world-of-agents/projects/<project>`, never in the project's folder, so a cloned repo can never bring a team or specialists of its own. Claude Code loads it as its own plugin, `woa-team`, from that project's own folder marketplace, so the specialists' names stay as they were (`woa-team:frontend-react-dev`).
- **One library for the PC.** Every skill lives once in `~/.world-of-agents/library`. A project's skills are simply its specialists' skills: give a specialist a skill from the library, and it reaches that project. Change a skill in the library and every project that uses it gets the new text; delete it, and the question first names every project and specialist that loses it.
- **New projects start empty.** On the Team page, a project with no specialists offers three ways in: **Add the starter team** (the eight you know, shown by guild before they're added), **Copy from another project** (a copy, not a link: no notes come along, and no skills, because both projects use the same library), or **+ Add specialist**.
- **The guard reads the session's project.** It finds the project from the folder Claude Code names for the session, never the folder an agent is working in, so an agent in a worktree, or one that ran `cd`, still gets its own project's team. A project with no team of its own keeps its guild leads, and their specialist starts are denied with the step that gives it one. A PC with no team at all starts no agent, as before.
- **Notes are per project.** A note a guild lead proposes belongs to the project it came from: it shows only on that project's Team page, and only there can it be approved.
- **The Team page is one project's.** A chip beside "Team" names the project and its folder. Tabs: Specialists, **Library** (it was Skills: every skill on the PC, grouped by where it came from, each saying how many projects use it, with its facts, who has it, who could get it, and its whole text) and Notes.
- **The pane says when a project has no team of its own**, and its Team button then reads **Give this project its own team**.
- **A fix in the pane.** The line about the plugin being on for every project said every session starts as the Lead/PM, which stopped being true in v3.8.0. It now says what is: its hooks run in every session of every project, where the guard lets only the Lead/PM edit files or start agents.

## Adding skills

- **Four ways in.** On the Library tab, **+ Add a skill** offers: **From your Claude skills**, **From GitHub**, **Paste a SKILL.md** and **Write a new one** (the form you know).
- **Your Claude skills.** The skills in `~/.claude/skills`, in two groups by who made them, as the desktop app's own list says: yours, and the built-in ones, which keep Anthropic's license (read it before you copy one) and mostly need their scripts. A skill the app's list doesn't name as yours or built-in goes in a third group, **Not labelled**, never under yours: a personal skill outside `synced/` always does, because its folder says where it sits, not who wrote it (an installer can write there too), and if that list can't be read, every skill does. Each row shows its file and says "In your library" when it is. Nothing is read until you open the list, and only the skill you pick is opened.
- **From GitHub.** Paste a link to a SKILL.md or to its folder (`github.com/<owner>/<repo>/blob/…`, `…/tree/…`, or `raw.githubusercontent.com/…`); the hall fetches that one file and nothing else. A link it doesn't take shows the three shapes it does.
- **One check screen.** Before anything goes into your library: its name and what it's for, to change if you like; where it came from, its license and what it costs every time a specialist that has it starts; what its header held that the library leaves out, with what `allowed-tools` and `hooks` would have done; the files its text names that don't come along; any reason it can't be added; and the whole text, line by line, with its flags. A skill's lines are flagged **overrides your rules?** when they talk about ignoring rules or the guard, acting without asking, keeping something from you, a `.env` file, or sending something to an address.
- **Check for update.** A skill from GitHub can fetch its link again and show the differences line by line, with flags on the new lines. **Take the update** or **Keep what I have**. Nothing is ever fetched again on its own.
- **Bigger skills, one cap per specialist.** A skill's text may be up to 20,000 characters (it was 8,000), and what it's for one line of up to 1,024. A specialist's skills may come to 40,000 characters together; its page shows what they cost every time it starts, with a bar that turns amber near the cap.
- **The library's facts box** shows a skill's repository and ref, its file and its license, where it has them.

## Security

- **The hall's first network use.** Adding a skill from GitHub, or checking one for an update, sends one HTTPS GET to `raw.githubusercontent.com`, built from the parts of the link you gave: no redirect followed, 10 seconds at most, the answer cut at 128 KiB, no cookie, no token, nothing of yours. It happens only when you press Fetch or Check for update. The page and the pane still never reach the internet.
- **What comes in is shown before it is saved.** A fetched or pasted skill gets the same refusals as one you write (no line starting with ``!` ``, no hidden characters), and what is saved is the hall's own copy of the text you saw, never something the page sends.
- **Only SKILL.md, ever.** Scripts and other files beside a skill never come along, from GitHub or from `~/.claude/skills`, where links and junctions are never followed and nothing but a SKILL.md is opened.
- **A header is read carefully.** It is parsed with `yaml` 2.9.1 (core schema, unique keys, at most 5 aliases, no custom tags); anything odd refuses the whole file, and every field the library doesn't keep is named on the check screen.
- **Teams stay out of your projects.** A project's team, its notes and the library live under `~/.world-of-agents`, where the guard and the setup's denies keep agents out, and the Team page can only ever read or change the project its link was made for.

## Updating from v3.8.0

In a terminal (Git Bash):

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.10.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then, in each project, once: type `/world-of-agents:setup-team-write` (or press **Give this project its own team** in the pane, which offers a copy or an empty team). It copies your shared team's specialists, switches and skill picks into the project, builds your library from the shared team's skills the first time, and leaves the shared team as an unused backup. Its notes are not copied: they wait on the project's Notes tab under "From your old shared notes", to keep for that project or drop, one by one. It then prints three commands to run once, in Git Bash, in that project's folder:

```bash
claude plugin marketplace add ~/.world-of-agents/projects/<project>
claude plugin uninstall woa-team@woa-local --scope local
claude plugin install woa-team@woa-<project> --scope local
```

and `/reload-plugins` in a session that is already open. Until then, the project's guild leads still work, and its specialists can't start.

When Claude Code asks whether you trust a project's folder (in VS Code, Claude Code 2.1.325 asks), say yes for a project you set up: a session in a folder you didn't trust starts without the project's settings, and so without World of Agents. The README's setup has the details.

Claude Code 2.1.312 or later and Node.js 20.19 or later, as in v3.8.0. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.10.0/README.md).
