Small fixes from the v3.0.0 install check.

## Fixes

- **The setup keeps your own rules.** An "Always allow" click adds a rule to the project's `.claude/settings.local.json`, and in v3.0.0 the next setup upgrade then stopped and wrote nothing, and so did a first setup in a project that already had such rules. Now a rule that no template version has is yours: the dry run lists it, quoted, with hidden characters shown as escapes, and the setup keeps it after the template's own rules. A first setup does this when `permissions` holds nothing but `allow`, `deny` and `ask` lists. If one of the template's rules is missing or changed, or anything else is in the way, the setup still stops and names the settings, never their values.
- **The pane warns when the plugin is on for every project.** It says "World of Agents is on for every project." and gives the command that turns that off: `claude plugin disable world-of-agents@world-of-agents --scope user`. Projects where you installed it with `--scope local` keep it. To know, the pane reads one key of your user settings, `enabledPlugins`, when the session starts, and nothing else of them.
- **The setup no longer promises Manual.** "Written." now says that Manual mode applies from the next new session, and that in the desktop app you should check the mode selector then: a mode picked for the folder wins, and in our tests the app used the file only in a git repository.
- **Turning it off for one project.** In a project where you installed it with `--scope local`, the desktop app's switch under Customize, then Plugins, is per project: on 11 Nov it wrote that project's `.claude/settings.local.json` and left the user settings alone. `claude plugin disable world-of-agents@world-of-agents --scope local` in the project folder does the same, and the pane's Node warning now gives that command.
- **The plugin's README installs from a terminal**, as the main README has since 11 Nov: `claude plugin install world-of-agents@world-of-agents --scope local` in the project folder, then `claude plugin list` shows no `Scope: user` entry for it. Not through the desktop app's Plugins screen, which asked for no scope and installed for every project.

## What changed

- **Claude Code 2.1.312 or later.** The pane now reads a setting with `$.settings.read`, which was measured on 2.1.312 and 2.1.319 only, and the desktop app ran it with its engine at 2.1.321. v3.0.0 needed 2.1.299.

## Updating from v3.0.0

In a terminal. Adding the marketplace again with a new tag is refused, and removing it uninstalls the plugin, so install it again in each project that had it:

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.0.1
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then run `claude plugin list`: no `world-of-agents` entry may say `Scope: user`. The setup's template hasn't changed, so `/world-of-agents:setup-project` says "Already set up" in a project you set up with v3.0.0.

Node.js 20.19 or later and the known limits are as in v3.0.0. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.0.1/README.md).
