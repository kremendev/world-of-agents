# v3.1.0 desktop check

For Dima, before the `v3.1.0` tag. Short steps; each says what you should see and which part of docs/v3.1-plan.md it
proves. Anything that doesn't match: stop there and note the step number.

## Before you start

1. In the repo, on the branch `v3-next`: `npm run dev:refresh`. It copies `plugin/` into `~/Downloads/woa-dev/plugin`.
2. A hall started before the refresh still runs the old page. Stop it first: in PowerShell,
   `Get-NetTCPConnection -LocalPort 4319 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess }`.
3. Open `~/Downloads/woa-m2-test` in the desktop app's Code tab, start a new session, pick **Manual** (the folder may
   remember another mode), and run `/reload-plugins`. The pane starts the new hall: open it with "Open hall".
4. Note the pane's plan-limit numbers (the 5-hour and weekly bars).

## 3.1a and 3.1b: the report format and the Reviewer on Opus

5. Type: **Have the Reviewer review hello.js for bugs.** Only the Reviewer should run.
   - The hall: the Reviewer walks to work, then a review row arrives from the Reviewer to the Lead/PM. (3.1a)
6. Click the Reviewer in the hall. The agent panel says **model: Opus**. (3.1b)
7. The report follows the format: a sentence or two, then Verdict, Files checked, Findings, Checks run and Left for the
   Lead, in that order, nothing after them. (3.1a; see the board steps below for how it shows)
8. The model, in Git Bash. It prints model names and counts only:
   `grep -oh '"model":"claude-[a-z0-9-]*"' "$(ls -td ~/.claude/projects/*woa-m2-test*/*/ | head -1)"subagents/*.jsonl | sort | uniq -c`
   Expected: `claude-opus-5-5` only. If the folder isn't there, the desktop app keeps its transcripts elsewhere: say so,
   don't count a blank as a pass. (3.1b; the same check passed in the terminal on 11 Nov)
9. Type: **Start the Reviewer on Haiku to review hello.js.** Either the Lead refuses (its prompt says never to pass a
   model), or its Agent call is denied with "the team's models are set in its agent files". The Reviewer must not run on
   Haiku: step 8's check, run again, still shows Opus only. (3.1b, D3)
10. The pane's plan-limit numbers again: a rough feel for what one Opus review costs on Pro. (3.1b)

## 3.1c: the Review board (Live, after step 5's review)

11. Click the Reviewer in the hall. The feed narrows to the Reviewer as before, and the **Review board** opens over the
    right-hand column. The hall doesn't move, shrink or change in any way. (3.1c, D9)
12. The card: "Review at HH:MM:SS"; a chip "Reviewer's verdict: …" (green Approved, amber Changes needed, red Couldn't
    review); the sentence or two; Files checked; Findings, each place like `hello.js:2` in code style; under Checks run,
    "The Reviewer says it ran:" with its list, then on its own line "The hall saw at least: Read 1, Grep 0, Glob 1" (the
    numbers the hall counted); Left for the Lead. No link anywhere on the board. (3.1c, D10)
13. Esc closes it, and the focus is back on the Reviewer. The Close button does the same. (3.1c)
14. The feed's review row reads "to Lead/PM: Review: Changes needed, 1 finding" (your numbers), with no Show all and an
    "Open review" button. It opens the board at that review. (3.1c)
15. Keyboard only: Tab to the Reviewer, Enter, Tab through the board (Close, then any Show buttons), Esc: the focus is on
    the Reviewer again. (3.1c)
16. Narrator (Win+Ctrl+Enter): open the board. It says "Review board, dialog", and reads the card in order. Narrator off
    again. (3.1c)
17. Make the window narrow, then zoom to 200%: the board sits under the hall where the feed was, and scrolls inside
    itself. (3.1c)
18. Optional, one more Opus review: "Have the Reviewer review hello.js again." The new card is on top; the first one is
    under "Earlier reviews", one line, collapsed, with a Show button that opens it. (3.1c)

## 3.1d: the "For you" strip and "Only for me" (Live)

21. Type: **Have the Backend dev add a comment to the top of hello.js, then have the Reviewer review it.** When the edit
    asks for approval, the strip at the top of the feed shows "Needs you · Backend dev · HH:MM:SS · Backend dev needs
    your approval". Approve it in the app: the item stays in the strip until you click it. (3.1d)
22. When the Lead answers, a "To you · Lead/PM" item shows the first line of its answer, about 80 characters. (3.1d)
23. Click the Designer in the hall (the feed narrows to the Designer), then click the "To you" item: the feed shows
    everyone again, the Lead's row has the focus (a ring around it), and the item leaves the strip. (3.1d)
24. Click "Only for me": it shows a tick and goes bold, and the feed shows only the flagged rows, read ones included.
    Click the Backend dev: only the Backend dev's flagged rows. Click it again to turn it off. (3.1d, D7)
25. Reload the page (F5): what you read stays read. (3.1d, D6)
26. Stop the hall (step 2's command) and start a new session so the pane starts a new one: the strip starts empty, and
    what the new hall sends is unread. (3.1d, D6)
