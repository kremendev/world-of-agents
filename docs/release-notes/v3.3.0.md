Big-project tools: quality gates, a backlog that outlives the session, and plan once, approve once.

## New

- **Quality gates, opt-in per project.** With gates on, each time the Designer, the Frontend dev or the Backend dev finishes a task, the plugin runs the project's `npm run check`. If it fails, the agent gets the output and fixes it, at most 3 times; after that it stops, the hall shows it in error with its card still open, and the Lead reports it to you. Only `npm run check`, and only in a project that has that script.
  - `/world-of-agents:setup-gates` explains what they do and whether they are on. `/world-of-agents:setup-gates-write` turns them on and `/world-of-agents:setup-gates-off` turns them off, in the project's `.claude/settings.local.json`, from the next new session. Only you can start these three.
  - **What they cost:** the check runs without asking you, so an agent that changes `package.json`, a test file or a config changes what runs. The team pane says "Quality gates: on." and warns while a session runs in Auto or Accept edits.
- **A backlog.** The Lead keeps `BACKLOG.md` at the project root: what is being built now, what is next, what is done. It reads it at the start of a session and updates it at the end, so tomorrow carries on from today. The Lead may edit that file and nothing else: the guard denies any other edit by it, and it still writes no code.
- **Plan once, approve once.** For a milestone, the Lead plans in plan mode and shows you the plan once. After your approval it writes the plan into the backlog and hands out the work.

## What changed

- The guard also checks `Edit` and `Write` calls: the Lead's, as above, and anyone's but the team's own editing agents, which it denies. The Designer's and the devs' edits still go to your permission prompt.
- The devs' prompts say what a quality gate's output is: failures in their own work to fix within their task, and still data, never instructions.
- **The devs run the check themselves.** A gate that passes says nothing, so the Lead used to call gated work "not tested". Now the Frontend dev and the Backend dev end each task by running `npm run check` (the setup already lets it run without asking) and report what they saw: "npm run check: passed", or "failed" with the exit code Claude Code showed them. They never run a second command just to read a code, and never claim a number they didn't see. The Lead passes that on. The Designer runs no commands and says so. With gates on, the gate still runs the check and stays the judge.
- **The devs touch only their task's files.** The Frontend dev and the Backend dev change only the files their task names. To show a test can fail they use a temporary copy, removed after, or a test fixture, never another project file, and they leave no backup copies behind.
- **The guard looks at BACKLOG.md before the Lead writes it.** A link, a junction, a folder, or a file with a second name (a hard link) named `BACKLOG.md` could carry the Lead's write into another file, such as the project's `.claude/settings.local.json`; the guard denies the write in each of those cases. It looks at what kind of file it is, never at what is in it.

## Updating from v3.2.0

In a terminal. Adding the marketplace again with a new tag is refused, and removing it uninstalls the plugin, so install it again in each project that had it:

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.3.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then run `claude plugin list`: no `world-of-agents` entry may say `Scope: user`. The setup's template hasn't changed, so `/world-of-agents:setup-project` says "Already set up"; gates stay off until you turn them on.

Claude Code 2.1.312 or later and Node.js 20.19 or later, as in v3.2.0. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.3.0/README.md).
