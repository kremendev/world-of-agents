Better reviews: a review board in the hall's page, the Reviewer on Opus, a "For you" strip, and Copy.

## New

- **The review board.** Click the Reviewer in the hall, or "Open review" on a review in the activity feed, and a board opens over the right-hand column; the hall itself doesn't move. The latest review is a card: the Reviewer's verdict (Approved, Changes needed or Couldn't review), the files it checked, its findings with file and line, what it says it ran, and what is left for the Lead. Earlier reviews of the run sit under it, one line each. Esc or Close closes it and puts the focus back where it was. It is a non-modal dialog, with real buttons and headings for keyboards and screen readers.
- **What the hall saw.** Beside what the Reviewer says it ran, the card shows, on its own line, how many Read, Grep and Glob calls the hall saw the Reviewer start: "The hall saw at least: Read 6, Grep 3, Glob 1". The Reviewer's own list is labelled as its word, never as fact.
- **A report format.** The Reviewer now ends its report with five fixed headings, which is what the card is built from. A report that doesn't follow them shows as written. A review is known by who sent it, the Reviewer to the Lead, never by what its text looks like.
- **The "For you" strip.** At the top of the activity feed: messages to you, approval waits and failures you haven't clicked yet, three at most, whatever agent the feed is narrowed to. A click opens the row and clears the item. What you have read is remembered for the hall you are watching, across reloads, and only as which row it was, never its text. **"Only for me"** narrows the feed to those rows.
- **Copy.** An opened row in the feed, and each review card, have a Copy button. It copies the text the way the page shows it: a Markdown link as its text, never its target. It leaves out invisible and control characters (bidi controls, zero-width characters, Unicode tag characters and the like), and says how many it removed.

## What changed

- **The Reviewer runs on Opus 5.5.** On the API, Opus 5.5 costs twice what Sonnet 5.5 does on every line ($4 and $20 per million input and output tokens, against $2 and $10, as of 11 Nov 2026). On a Pro or Max plan the cost is how fast reviews use up your limits, which the pane shows. The Lead stays on Opus, and the Designer and the two devs on Sonnet.
- **The guard denies an Agent call that chooses a model.** The Agent tool's `model` argument overrides an agent's own file, so without this a call could run the Reviewer on a smaller model, or any agent on a far dearer one. The agent file's model now always wins.
- **The guard denies remote agents.** An agent start may run as usual or in a git worktree on your PC. `isolation: "remote"` would run the agent in a cloud environment, out of reach of the plugin's hooks and the hall, so it is denied, and so is any isolation the guard doesn't know.
- **The plugin's scripts start only when run themselves.** Each hook script used to run its main part whenever the file Node was started on merely ended with its name, so another file named, say, `xguard.mjs` that imported the guard ran it too. Each now compares real paths. Nothing changes in normal use.

## Updating from v3.0.1

In a terminal. Adding the marketplace again with a new tag is refused, and removing it uninstalls the plugin, so install it again in each project that had it:

```bash
claude plugin marketplace remove world-of-agents
claude plugin marketplace add kremendev/world-of-agents#v3.1.0
claude plugin install world-of-agents@world-of-agents --scope local   # in each project folder
```

Then run `claude plugin list`: no `world-of-agents` entry may say `Scope: user`. The setup's template hasn't changed, so `/world-of-agents:setup-project` says "Already set up" in a project you set up with v3.0.1.

Claude Code 2.1.312 or later and Node.js 20.19 or later, as in v3.0.1. Setup and the full security notes are in the [README](https://github.com/kremendev/world-of-agents/blob/v3.1.0/README.md).
