Nothing here is built, and nothing is built before he approves it. It replaces this file's earlier plan, the hall redrawn

## The prototype (Checked)

- **Code:** `town/src/`, plain JavaScript. `world.js` is pure data: rooms, spots, roads, the walking graph, `route()` and
  `routeFromNode()`. The 3D is ten modules, about 300 KB, that `build.py` joins into one HTML page by patching
  `base.html` as text (with asserts); `base.html` still holds an older map and 3D module the build cuts out. three r160
  comes from cdn.jsdelivr.net through an import map. Its checks are its own: `check.sh` (two page walks on a stand-in
  three, Playwright and Chromium), `compare.cjs`, `seats.cjs` and `shot.cjs` (real three r160, software WebGL). None of
  it is linted or in `npm run check`.
- **The world:** the nine areas (the town calls the War room the War hall), each with its doors, floor and spots; eight
  buildings nobody works in (barracks, store house, stable, granary, windmill, watch tower, shrine, camp), the dock, the
  altar, a stream and a pond, and, by its commit bcbe7a9, four far isles with trees from the Blender flora set. Houses
  open: a toggle folds their upper walls away, and the cut edges don't flicker (`separateCut()`).
- **The look:** `MeshToonMaterial` with a three-step gradient and a rim term patched into its shader
  (`onBeforeCompile`), inverted-hull ink on built shapes, and every frame two renders of the scene: one of normals and
  depth, then the scene itself into a 4x multisampled target; then a screen-space ink pass (silhouettes from depth,
  creases from normals), bloom and a colour grade that reads depth. PCF shadow maps. Early-evening light.
- **The characters:** five Tripo models, one mesh, one material and one JPEG beside it each, on a 65-bone `mixamorig`
  skeleton, with four clips: `idle`, `walk`, `sit` and `play_mobile_game` (the desk work). The town's poses map onto them
  (`CLIP_FOR`): typing and the orcs' smash play the phone clip; sitting and drinking play `sit`; sparring, painting,
  reading, pointing and planning play `idle`. Heights: the goblin 1.32 m, the elf 1.78, the female orc (Frontend dev)
  1.92, the reaper (Reviewer) 1.95, the male orc (Backend dev) 2.18. A seated model goes with its hips over the seat and
  two-bone IK bends its legs to the floor: 40 of 40 seats within 0.4 cm (`seats.cjs`). Each file keeps Tripo's AIGC
  label in `asset.extras`: the producer's company code and the model's ProduceID, nothing about the account.
- **The run:** its own 13-step script with four states (work, idle, needs, walking), not the app's nine states or
  `DEMO_RUN`.
- **Stand-ins:** every Blender model and every character has a hand-built stand-in (`m2b-gate.js`, the hand-built
  houses, `m6-cast.js`), because an artifact's fetch can fail or come late (20 s).
- **The files:** `.gltf.json`, the buffers inside as base64 `data:` URIs, because artifacts don't serve `.glb`; the page
  makes each into a GLB in memory before `GLTFLoader.parse()`. Packed by `tools/pack_gltf.py`: `KHR_mesh_quantization`
  required in all 22 files, `KHR_materials_emissive_strength` used in 9 scenery files, no Draco, Meshopt or KTX2.
  `plainModel()` unpacks each as it loads.

## States and places

**Decided:**

| State                               | Place                 | What shows                        |
| ----------------------------------- | --------------------- | --------------------------------- |
| writing, reading, thinking, waiting | the agent's work spot | the work, its screen lit          |
| needs-you                           | its work spot         | hand raised, and the HUD's banner |
| error                               | its work spot         | a marker over it                  |
| done, idle                          | idle life             |                                   |

Idle life: the orcs spar, drink or hammer; the Designer paints; the Lead wanders; the Reviewer reads. **The rule:** the
world never shows work that isn't happening, and a real event pulls the agent back at once. (`walking` is a state no
event sends, today too: it is what the world does between places.)

The places come from the app's own events through `officeReducer()` and the place map, never from the town's script.

**Proposed**, so the rule holds:

- **Idle life only in the idle areas** (Tavern, Training yard, Courtyard, Garden), never in a work room or at the Forge.
  An orc hammering by the furnace, the Designer painting in the studio or the Reviewer reading in the Library would look
  like work. So the orcs hammer at the Training yard's anvil, the Designer paints at an easel in the Garden, the Reviewer
  reads on a Courtyard bench or by the Tavern fire, and the Lead wanders the outdoor paths, never into a work room.
- **The prototype breaks that rule (Checked).** Its `IDLE` table sends idle agents into work places: the Reviewer only
  to the Library (`lib-chair`, `lib-shelf`), the Lead to the War hall's rug (`war-rug`), the Designer to the studio's
  easel (`studio-easel`), the Frontend dev to the Forge's anvil (`forge-anvil`); the built page even starts four of the
  five there. The port drops those spots from idle life. The town already has places for most of it (the Garden's easel
  and pond, the Training yard, the Tavern, the Courtyard's bench and well); the Reviewer needs a reading spot outside the
  Library, and the Training yard an anvil (Checked: the town's are at the Forge and in a house). **Question** (before
  4b): hold the rule this way.
- **"At once" means from where it stands.** A work event ends the idle activity on the spot, and the agent walks
  straight back, turning mid-path if it was walking. Today's 2D walker finishes a walk before it takes the next one; the
  town's graph already routes from any node (`routeFromNode()`), so turning mid-path is a port, not new work. That walk
  goes at the 2.5x hurry, as today.
- **The 3 s desk time (2d).** Today an agent whose work ends less than 3 s after it sat down keeps showing that state for
  up to 3 s, so it doesn't bounce. Under the new rule it may stay seated those 3 s, but its screen goes dark and its work
  animation stops at once. **Question** (before 4b): keep the seat hold that way, or drop it.
- **Places that depend on the task.** Today a Reviewer reading another agent's task reviews at that dev's desk, a Lead
  reading one stands in the dev room, and a waiting Lead in Live stands there too (`destination.ts`). Proposed: keep
  them, counting that desk and the Workshop as the work spot for that task, because the work really happens there. (The
  town's script has the Reviewer at the Library desk only.) **Question** (before 4b): that, or the strict map (the
  Reviewer always in the Library, the Lead always in the War room).
- **Carried over unless Dima says otherwise:** the devs fetch their task scroll from the War room before going to their
  desks; the orcs smash their keyboards while writing ("!!"; no clip yet, so the town plays the phone clip with sparks
  over the keyboard); a message's bubble never shows while its agent walks, and its time runs only while it is on
  screen; small talk between two or more idle agents in the same idle area (our flavour text, never agent output).

**The Forge (Decided):** the furnace still shows how busy the keep is. Screens glow only while their owner works.
**Proposed:** today's furnace rules in 3D. The mouth's colour follows 0 / 1 / 2+ working agents, and the glow grows up to
4, as a glowing material and one light. Fires and candles flicker, each in its own phase. With reduced motion the

## Tech

**Decided:**

- three.js as an npm dependency, pinned to an exact version and bundled by Vite. No CDN at runtime: the page still loads
  only from its own hall (`connect-src 'self'`), and the hall's one network call stays the GitHub one.
- The scene is its own module; the HUD stays React.
- Without WebGL, the page falls back to today's 2D hall.
- Rendering pauses while the tab is hidden; the pixel ratio is capped at 2.

**Proposed:**

- **Where the code goes:** `src/world/` holds pure TypeScript: the town's layout, spots, roads and path graph from
  `world.js`, the state-to-place map, idle life's schedule and the camera's views, all tested in Vitest with no WebGL.
  `src/world/scene/` holds three.js alone, ported from the town's modules. React talks to the scene through one small
  interface (mount, update with the office state, select, follow, fly to a room, open houses, dispose). The scene never
  imports React, and React never touches a three object.
- **three's version:** the town runs r160 (December 2023) and its checks ran against it. Proposed: pin the newest release
  at 4a, `@types/three` to match, and run the ported checks on it; r160 only if something breaks that 4a can't fix.
- **Loaded on demand:** the scene and three come in through a dynamic `import()`, so the HUD and the 2D fallback don't
  wait for them. three will be the biggest part of the page; 4a measures it and writes it down.
- **WebGL 2:** three.js renders with WebGL 2 only. The page asks for a WebGL 2 context first. With none, with a scene that
  fails to load, or with a lost context that doesn't come back, it shows the 2D hall. jsdom has no canvas context
  (`setup.ts` returns null), so every test that exists today keeps running on the 2D hall.
- **One path, no stand-ins.** The town's hand-built stand-ins exist because an artifact's fetch can fail. In the app the
  models ship with the page from its own origin, so for every part that has a model the port takes the model alone, and
  a model that fails to load shows the 2D hall, as no WebGL 2 does. Hand-built stays where there is no model: the island's
  top, the sky, the roads, the props, the scatter, and the lights and flames (they animate). That leaves out
  `m2b-gate.js`, the hand-built houses and walls, and `m6-cast.js`'s figures (whatever of its rigs moves the models,
  4b keeps).
- **The 2D hall is frozen** as the fallback: it keeps working and keeps its tests, but new world features aren't drawn
  there. That works because of the accessibility rule: everything the world shows is also in the HUD.
- **Cel shading and outlines:** the town's (Checked, above): `MeshToonMaterial` with its gradient and rim term, the
  inverted hulls, the screen-space ink pass, and the characters' JPEGs on toon materials. This replaces the plan's
  `OutlineEffect`. `onBeforeCompile` and `ShaderPass` take GLSL text, which WebGL compiles; no JavaScript is evaluated.
- **Performance:** the town draws far more than this plan proposed (two renders of the scene a frame, a 4x multisampled
  target, shadow maps, bloom, the ink pass and the grade, where the plan had blob shadows and no post-processing).
  Proposed: port its look whole, then measure a frame on this PC at 100%, 125% and 150% Windows scaling in 4a and write
  the numbers down; if it is too slow, the shadow maps go first, then bloom's resolution, before anything that makes
  the style. One loop through `renderer.setAnimationLoop`, stopped on `visibilitychange`;
  `Math.min(devicePixelRatio, 2)`, as the town has.
- **Labels:** name tags and bubbles stay HTML over the canvas, placed from 3D each frame (the town does this with
  `textContent`), `aria-hidden`, with today's overlap rules (`settleLabels()`) and rem minimums. They are moved through
  `element.style`, which the CSP allows, never through a `style` attribute.

- **No Git LFS.** A plugin installed from GitHub is a git clone, and whether a clone fetches LFS files depends on the PC's

## Security

**Decided:** models are our own bundled files only, loaded with three's `GLTFLoader`. No remote models, no eval, and the
CSP stays as it is.

**Proposed**, to keep "the CSP stays as it is" true:

- **No images packed into a GLB.** `GLTFLoader` turns an image packed inside a GLB into a `blob:` URL and loads it from
  there, and the policy (`default-src`, `img-src` and `connect-src`, all `'self'`) doesn't allow `blob:`. The models
  already keep this (Checked): the scenery has no images, and each character's only image is its JPEG, a file beside it,
  served from the page's own origin. 4a checks it in Edge with two test models under the policy: one with a packed image
  must fail, and one without must load. If that turns out wrong, `blob:` still doesn't go into the policy without Dima's
  say.
- **No compressed models:** no Draco, Meshopt or KTX2. Their decoders are WebAssembly, and Draco's runs in a worker made
  from a blob, so they would need `'wasm-unsafe-eval'` or `worker-src blob:`. The models keep this too (Checked): plain
  glTF, `KHR_mesh_quantization` and `KHR_materials_emissive_strength` only, both read by `GLTFLoader` with no decoder.
- three.js uses no `eval` and no `new Function`. 4a checks it the way Zod's jitless mode was checked: the hosted demo's
  meta policy reports nothing.
- **Nothing an agent sends becomes a model, a texture, a URL or a 3D text mesh.** Agent text stays React text in the HUD
  and in HTML bubbles. A model's URL comes from our bundle, never from an event, and so does the JPEG a GLB names.
- **The dependency:** an exact pin (no `^`), `npm audit` clean, and any install script blocked like every package's (three
  should have none). `@types/three` is pinned to match. An upgrade is a task of its own.
- The Pages demo carries the same policy as a meta tag, and the scene must load there too.
- **The AIGC label stays** (Checked: the producer's company code and the ProduceID, nothing about the account).
- **Flag, outside the app: the Blender runner.** While its window is open it runs any `.py` that lands in
  `Documents\WoA-models\jobs`, as Dima, with Blender's full Python. Anything that can write a file there can run code:
  a download, a script, an agent's edit he approves. The guard doesn't cover that folder. The README already says to
  close it after a batch. Proposed, for `tools/models/`: the runner runs only jobs whose SHA-256 is in a list it reads
  at its start.
