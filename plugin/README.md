The World of Agents plugin for Claude Code: five agents (Lead/PM, Designer, Frontend dev, Backend dev, Reviewer) and the hooks that report what each one does to the Forge Hall, a small server on 127.0.0.1.
It starts with `woa`. Up to v2.2.0 it needs the hall running (`npm run hall`) to show anything; from v3.0.0 it carries a prebuilt hall (`hall/`) and the team pane starts it. Setup, security notes and known limits are in the [main README](../README.md).

To install it for one project, run `claude plugin marketplace add kremendev/world-of-agents#v3.4.0` once, then `claude plugin install world-of-agents@world-of-agents --scope local` in a terminal in the project folder, and check that `claude plugin list` shows no `Scope: user` entry for it. Not through the desktop app's Plugins screen: on 11 Nov 2026 it asked for no scope and installed for every project. Never user scope: the Lead would become the main agent in every project.

Two parts answer back. The guard hook (`hooks/guard.mjs`) can only deny: an agent start outside the team's table, or a shell command that names a `.env` or `.envrc` file. Since v3.1 to v3.4 it also denies an Agent call that sets a model or runs the agent remotely, the Lead's edits to anything but `BACKLOG.md` (and to a `BACKLOG.md` that is a link or a second name for another file), and any agent's Edit or Write into `~/.world-of-agents` or into an agent memory folder (`.claude/agent-memory-local`, `.claude/agent-memory` or `~/.claude/agent-memory`: agent memory is off). `/world-of-agents:setup-project` shows, and `/world-of-agents:setup-project-write` writes, Manual mode, subagent depth 2 and a safe-command list into the project's `.claude/settings.local.json`, copied from `skills/setup-project/template.json` by a script Claude Code runs. Settings that are exactly an earlier template (`skills/setup-project/versions/`) are upgraded, and every other setting stays as it is, rules you added yourself included; a first setup keeps rules a project already had in its `allow`, `deny` and `ask` lists. You type both; the model can't start either.

The team pane (`hooks/mod/`, a mod) only watches: it shows the five agents, who waits for your approval, a warning in the modes that don't ask first (Auto, Bypass permissions, Accept edits), a warning when your user settings turn the plugin on for every project (the one setting it reads), context and plan limits, the token ledger ("This PC"; every Claude Code session on this PC once you press "Recount"), three preset prompts, a link to the hall, and "Change skills", which opens the hall's Team panel through a one-time link and lists each change to the team. It appears after the first message, and `/world-of-agents:team` (yours only, like the setup skills) opens it again after you close it. It never answers a tool call, a check or an agent start, and it never sends a prompt: a preset puts its fixed text after your draft in the prompt box, for you to send.

The pane also starts the hall (`node hall/server.mjs`, from the plugin's own folder, no arguments) when nothing holds port 4319, after `hooks/hall-check.mjs` has asked the port the way `send.mjs` does: only a hall that answers the handshake for the token, as this plugin's version, counts as ours. Another install's hall gets a line naming its version, and no link; if another program holds the port, it says so. Either way it starts and stops nothing. On Windows it speaks two things, who needs your approval and that the team is done, through `voice/speak.ps1`, started with a fixed argument list and the text on stdin only. Mute keeps it quiet in later sessions too.

**Requires Claude Code 2.1.312 or later, and Node.js 20.19 or later on PATH.** The guard fails closed: without Node, every agent start and every Bash or PowerShell command in a project with the plugin is blocked with `hook error: [node ${CLAUDE_PLUGIN_ROOT}/hooks/guard.mjs]: failed; blocking because onFailure is "block" Error occurred while executing hook command: Executable not found in $PATH: "node"`. Install Node, or turn the plugin off for that project: `claude plugin disable world-of-agents@world-of-agents --scope local` in the project folder, or the desktop app's switch under Customize, then Plugins, which for a local install writes that project's own settings (checked 11 Nov). The pane checks for Node at the first message and says the same. With a Node older than 20.19 the hall can't start.
